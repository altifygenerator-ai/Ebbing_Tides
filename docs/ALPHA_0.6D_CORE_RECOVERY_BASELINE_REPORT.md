# Alpha 0.6D — Core Experience Recovery Baseline Report

This report corresponds to the functional baseline produced from the Alpha 0.6D Master Implementation Directive. It is **not** a claim of final visual/feel approval.

## 1. Files changed

Primary implementation changes include:

- `src/alpha/main.ts`
- `src/game/portActions.ts`
- `src/game/characterMind.ts`
- `src/game/playerFacing.ts` (new)
- `public/alpha/styles.css`
- `tests/alpha-06d-core-recovery-baseline.test.mjs` (new)
- `tests/alpha-06d-skeldra-benchmark.test.mjs` (new)
- updated identity cleanup regression to reflect 0.6D's restrained-symbol rule
- 0.6D audit/design/report documentation

Compiled Alpha JS is regenerated by `npm run alpha:build`.

## 2. Systems preserved

Preserved: 120×80 / 20 nm world, pathfinding, physical distance, NPC Plan Until Interrupted, economy, history/genealogy/politics, knowledge/belief split, relationships/memories, inventory/equipment, character stats/skills/abilities, ship/content registries, combat foundations, save/load schema v10, UI Production Architecture Recovery, ArtDirectedCanvas/calibration, Art-Skinned Dynamic UI, Reference Ghost infrastructure and accepted visual anchors.

## 3. Systems hidden / simplified

- direct Attunement management removed from normal play,
- exact relationship dimensions hidden behind qualitative states,
- raw knowledge confidence demoted to qualitative confidence,
- raw market stock/target detail demoted to actionable shortage/surplus reads,
- persistent application-style port activity navigation removed,
- ship overview demotes non-actionable technical state,
- personal-combat stance choices remain available but are collapsed behind one control,
- identity symbols reduced to supporting marks.

## 4. Systems removed

Removed from normal production UI: direct Attunement slider, repeated manual voyage tick controls, directional map-pan arrows, development/milestone labels, production-facing simulation explanations and redundant recurring activity navigation.

## 5–9. Navigation / camera / LOD / Sail / Search Waters

See `ALPHA_0.6D_NAVIGATION_EXPERIENCE.md`. Navigation now uses drag, bounded smooth zoom, global/regional registered art, crisp dynamic overlays, click-to-route, physical NM/ETA/supply estimate, Sail Until Interrupted and Search Waters. Zero supplies never blocks travel; hardship proceeds underneath.

## 10. RPG gameplay-impact changes

A new build-sensitive port assessment action turns background/profession into different information channels: underworld, trade, industrial, scholarly, maritime or social. Existing skills continue to affect navigation, combat, trade, progression and specialist actions. The permanent matrix is in `RPG_SKILL_GAMEPLAY_USAGE_MATRIX.md`.

## 11. Attunement

No player slider. Derived specialization only, qualitative when relevant, neutral ordinary baseline. Exact underlying state remains available for advanced Arcane/Industrial compatibility experiments. See `ARCANE_INDUSTRIAL_SPECIALIZATION.md`.

## 12. NPC / relationship presentation

NPC relationship presentation is qualitative. Character Mind context now incorporates remembered canonical events. Selected dialogue branches react to profession, skills and religion without printing explicit `[Skill X check]` syntax. Conversation-generated memories can enter the NPC memory stream.

## 13. Economy presentation

Markets preserve real simulated stock/prices but surface the most actionable shortage/surplus information as captain-facing qualitative intelligence. Commerce improves the quality/quantity of that read.

## 14. Ship / combat tightening

Ship overview emphasizes ship art/build role plus Hull, Sails/Rigging, Crew, Cargo, Guns and Supplies. Damage states appear when meaningful. Harbor work is contextualized under the current port. Naval actions use clear verbs; personal combat keeps Attack / Fire-or-Reload / Defend / Stance / End Turn while retaining deeper AP/equipment/stance calculations.

## 15. UI / art changes

No recovery architecture was discarded. Port actions are contextual, Journal is reorganized around player questions, recurring symbols are restrained, and new presentation helpers are semantic/code-owned rather than painted duplicate geometry.

## 16. Provisional art still requiring replacement

See `ALPHA_0.6D_PRESENTATION_ASSET_SHARPNESS_AUDIT.md`. Thorenfjord still lacks dedicated establishing art. Skeldra close-navigation art remains subject to manual sharpness judgment; if inherently soft, re-author rather than apply CSS sharpening. Naval tactical presentation retains its known production-art limitations.
